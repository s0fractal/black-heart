## Що лишається

Питання, 8 карт, ключ, чотири порядки, пороги та пріоритет рішення з
[PLAN.md](PLAN.md) незмінні. Використовуються байти `cards.json`,
`review-key.json`, `schedule.json`, `execution/stimuli/1–4.txt` і `execution/score.py`
з базового коміту. Карти й стимули не копіюються в новий комплект.
A = `claude-sonnet-5`, B = `claude-opus-5`, native Claude Code / Max,
medium effort. Чотири свіжі сесії A1, B1, B2, A2, по 180 секунд максимум.
Усі 32 позиції звітуються; жодного повтору, continuation чи заміни моделі.
Результат описуватиме тільки ці навчальні карти всередині родини Claude.
Рецензент ключа також Claude; незалежності між провайдерами не заявляємо.

## Дві зміни

1. **Прибрати рівність усіх полів init і локальну HTTP-пробу з кожного слота.**
   Новий каталог поза Projects, новий процес, native login, вимкнені пам’ять,
   CLAUDE.md, інструменти, slash commands і MCP: налаштування `runtime.py`
   з базового коміту. Перед запуском фіксуються версія CLI, команда, середовище
   без секретів і дайджест промпту. Бінарник пінується за sha256 до рев’ю
   пакета й звіряється перед кожним слотом; DISABLE_AUTOUPDATER лишається.
   Немає sandbox-проби, що змінює мережу
   або Unix-сокети відносно живого клієнта; немає proxy переписування запитів.
   У живій трасі потрібен один init, правильний model, порожні tools,
   mcp_servers, skills, slash_commands і plugins та відповідна модель assistant.
   Socket path розглядається як можливий вхідний канал, не доказ ізоляції.
   У трасі заборонені події user; --replay-user-messages не вмикається.
   Потрібні рівно одна подія assistant і один result із цілим num_turns == 1
   (boolean не приймається). Єдині дозволені події: system/init,
   system/api_retry, assistant, result, rate_limit_event. Інший system subtype
   або будь-яка інша подія, зайвий хід чи відсутній result — INVALID.
   Інші поля init зберігаються; сам новий діагностичний ключ не є відмовою.
   Це контроль видимої траси, не гарантія виявлення всіх socket-повідомлень.
   Операторові й іншим агентам заборонено надсилати щось у сесію анотатора.
   Бажане вікно без інших сесій Claude; якщо вони є, до та після слота
   записати PID, час запуску й executable, без чужих промптів або секретів,
   і перелічити їх в аудиті. Знімки процесів не доводять відсутності інших
   сесій протягом усього інтервалу. Чужі сесії не завершувати автоматично.
   Якщо є штатне вимкнення міжсесійних повідомлень, використати його після
   перевірки й записати в пакет; наразі такого прапорця в --help не знайдено.
   Доказ про пам’ять — історичний позитивний контроль
   [canary](execution/context/canary-hardened.json) разом із
   [позитивною умовою](execution/context/canary-positive-control.json):
   посилатися лише за збігу бінарника й прапорців. Контроль ішов під sandbox,
   що дозволяв файлове читання, але змінював умови для Unix-сокетів;
   він не підтверджує ізоляцію каналу повідомлень у живій сесії.
   Виявлене виконання інструмента, сторонній контекст або невідповідність
   переліченим суттєвим умовам — INVALID і зупинка. Відсутність такого
   спостереження не доводить відсутності прихованого контексту провайдера.

2. **Дозволити одну зовнішню огорожу без виправлення JSON.**
   Спочатку прибрати лише зовнішні пробільні символи. Прийняти або голий
   JSON-об’єкт, або весь текст між точною початковою лінією ` ```json `
   (без пробілів навколо трьох backticks та json) і кінцевою лінією ` ``` `
   (так само без пробілів). Переноси LF або CRLF; після закриття лише пробіли.
   Ніякої прози навколо, другої огорожі, пошуку об’єкта всередині тексту,
   виправлення лапок чи повторного запиту. Внутрішній текст проходить
   незмінний строгий `score.answer`: дублікати ключів/ID та хибна схема — відмова.
   Сирий result зберігається незмінно; окремо — спосіб розбору bare/fenced.
   Стимул і далі просить голий JSON; огорожа є дозволеним транспортним варіантом.
   Нормалізований текст використовує старий scorer тільки для нових сесій.
   Кількості bare/fenced/невалідних відповідей показати окремо за моделями;
   дозволений спосіб оформлення не впливає на оцінку розмітки.

## Найменший достатній пакет

Один тонкий адаптер до наявних runtime, запису публічних подій і scorer;
без нового движка, дублювання карт, бандлів або нового API-перехоплювача.
Окремий каталог `retry-2`, незамінні зайняті слоти, сирі події/відповіді,
версія клієнта, reported usage, формат, модель і кількість api_retry.
Між слотами — окремий аудит із хешами; запуск після нього окремою командою.
Таймаут після підтверджених суттєвих умов — помилка формату; без result
із num_turns == 1 одноходовість не підтверджена, тому це INVALID. Інші
відсутні суттєві свідчення або збій клієнта також дають INVALID. Старі результати не включаються.
До сесій перевірити лише змінені межі: bare/fenced та зайвий текст/дублікати,
дозволений socket field проти непорожніх skills, user/зайвий assistant,
невідомий system subtype, num_turns != 1 або відсутній result/init/model,
неможливість повторного слота. Історичний scorer і матеріали не переписувати.
