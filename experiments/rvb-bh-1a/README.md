## Що вже перевірено офлайн

`probe.py` на коді Black-Heart `d8e3432` дає 7/7 перевірок:
редукція S K K I з бюджетом 0 призупиняється, з бюджетом 2 досягає I;
підпис приймає вихідні байти та відхиляє змінені; синтетичний predicate
PolyglotAuditReport відхиляє порожній звіт і звіт з помилкою, приймає звіт
із позитивним seal. Останнє — лише метод dataclass, не справжній PDF-аудит.
Жодної особи, семантичної відповідності чи істинності цілого документа
цей запуск не перевіряв. Ключ для таких питань потребує рев’ю людиною/рецензентом.

Чотири навмисні підміни копій квитанції (SUSPENDED → SETTLED, прийняття
змінених байтів, порожній SOUND, SOUND з error) виявляються. Це чутливість
нашої перевірки квитанцій, не mutation testing реалізації Black-Heart.

Перша спроба помилково очікувала текст `I` замість друкованого `🤍`.
`development/offline-v1.json` і `development/probe-v1.py` збережено як історію
невдалого oracle; цей архівний скрипт не призначений для запуску зі свого нового
каталогу. Виправлена версія порівнює терми структурно, квитанція — `offline.json`.
Це підготовчий офлайн-цикл до пререєстрації, не прихований повтор модельної сесії.

Повторити перевірки без моделі, у новий файл під домашнім каталогом:

```sh
python3 experiments/rvb-bh-1a/probe.py "$HOME/rvb-bh-1a-offline-check.json"
```

Дайджести матеріалів містить `sha256.json`; код бібліотеки й хеш probe —
у квитанціях. Точний Python там теж записано. Це unsigned operator evidence.
Офлайн-успіх показує придатність цих конкретних механічних фікстур;
стабільність розмітки моделями ще не виміряна. Глибока інтеграція відкладена.

## Уточнення після рев’ю 8687a93

S2 тепер прямо стверджує належність ключа людині (OPEN), а не те, що
підпис її встановлює. Рубрика розділяє ці дві форми твердження. Для D1/D2
булеві поля перейменовано на результати is_sound(), додано явні лічильники
трьох синтетичних станів. `receipt_field_mapping` зберігає відповідність
історичній offline.json без зміни її байтів; це пояснення оператора,
не нова виміряна квитанція. Ключ містить пояснення для всіх восьми карт.

`validate_cards.py` перевіряє джерела й дайджести, відображення квитанцій,
конструювання станів через фактичний клас звіту та повторний локальний
collect(). Це офлайн-перевірка відповідності карт, не модельна сесія:

```sh
python3 experiments/rvb-bh-1a/validate_cards.py
```
